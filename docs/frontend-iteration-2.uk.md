# Frontend · ітерація 2 · 10 вересня 2026

Реалізація в реальному React/Wails frontend на базі HEAD `410051f`. Зміни не закомічені. Фідбек користувача має пріоритет над старими естетичними правилами. Новий напрям: щільність, насичений колір, виразна контекстна motion, прозорі шари, floating Dock/Play. Перемикачі просторого UI та меншого руху не повертаються. Системний accessibility preference `prefers-reduced-motion` залишається.

## Що переглядати

Запуск frontend із прикладами: `cd frontend && VITE_DESIGN=1 npm run dev -- --host 127.0.0.1 --port 5193 --strictPort`.

- Звичайний перегляд: http://127.0.0.1:5193
- Крайні випадки: http://127.0.0.1:5193/?stress=1 — 10 голосів, 24 проєкти, 12 нотаток.
- Це реальні компоненти застосунку з development adapter. Приклади виключені з production bundle; їхні зміни скидаються після reload. Browser demo не викликає AI й не записує звук.
- Нативний frontend звертається до Go/Wails bindings. Нові нотатки зберігаються у SQLite, домовленості — в наявному JSON summary, embeddings — у локальному кеші SQLite.

## Пошук і реальні технічні межі

`SearchKnowledge` будує корпус із SQLite. Точний режим порівнює всі введені фрагменти тексту без регістру; це буквальний пошук, не морфологічний і не новий FTS-індекс. Семантичний режим використовує наявний `text-embedding-3-small`, 512 dimensions; кеш ідентифікується джерелом та hash заголовка/тексту. Змінені документи отримують нові vectors; старі ключі вилучаються при наступному semantic search. Відповідь отримує до 16 джерел із типом і номером. Пошуковий UI показує до 60 результатів.

Корпус не має обмеження на кількість зустрічей. Прямі джерела видалених зустрічей і їхні notes виключені; власний стан проєкту залишається окремим документом. Перший semantic search індексує відсутні фрагменти пакетами по 32; timeout — 3 хвилини, завершені пакети кешуються. Для дуже великого архіву ще потрібні benchmark, фоновий progress та пошуковий індекс замість повного читання корпусу на кожний текстовий запит. Список записів і palette наразі читають до 10 000 записів; віртуалізація й pagination не додані.

Прийняття нової редакції summary не перебудовує автоматично вже сформований стан проєкту. Перебудова доступна на сторінці проєкту. Щоб показувати точний diff «що змінилося після зустрічі», потрібні версії state/операцій із provenance. Для цитати під кожним summary-рішенням потрібен структурований source link від генерації, а не пошук схожої фрази постфактум.

Live markers потребують session ID, збереження міток до появи recording ID, перенесення після завершення й правил для короткого/відкинутого запису, crash recovery та ручної зупинки. Локальні тимчасові мітки, які зникають після закриття панелі чи завершення запису, не видаються за готову функцію.

## Сценарії agenda / семантичного brief

| Сценарій | Що доступно зараз | Що потрібно для наступного кроку |
|---|---|---|
| Одна зустріч із summary | Рішення, дії, питання, notes, transcript | Точна provenance кожного висновку |
| Зустріч без summary / без AI-ключа | Текст і ручні notes; локальний пошук | Детермінований brief не повинен вимагати AI |
| Зустріч у процесі / помилка | Реальний processing state і доступний текст | Не включати незавершений live-текст як остаточний факт |
| Проєкт із багатьма зустрічами | Поточний state, відкриті питання → agenda note | Версії й часовий diff, актуальність state після ручної правки |
| Проєкт без зустрічей, лише notes | Notes і пошук / Q&A по них | Дата змін нотаток для добового brief |
| Повторена домовленість у кількох зустрічах | Наявний project-state / deterministic grouping | Стабільні зв’язки між ручною справою й зведеною project item |
| Суперечливі notes, summary і рішення | Типізовані джерела в Q&A, prompt просить пояснити суперечність | Явні дати/редакції та правила пріоритету джерел |
| Кілька проєктів і позапроєктні зустрічі | Архівний Q&A та локальний пошук | Часові й контекстні фільтри для цільового daily brief |
| Виконане / скасоване / прострочене | Реальні стани, приховування done, існуючі правила overdue | Не відновлювати завершене завдання з давньої репліки |
| Видалене / відновлене | Корпус враховує актуальний стан SQLite | Перевіряти пов’язаний persisted project state окремо |
| Немає релевантних джерел | Явна відсутність відповіді | Не генерувати «корисну» вигадану agenda |
| Великий архів / відсутня мережа | Exact локально, semantic з явною помилкою | Фонове індексування, progress, cancellation, benchmark |
